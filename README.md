# CORTEX ROBOTICS — Recruitment Drive

A career-fair / recruitment intake tool:

- **Public page (`/`)** — the link you share with applicants. They pick
  "Intern", "Graduating / Job-seeking", or "Already Working" and the form
  asks for the right documents: Resume + Academic Transcript (PDF only) for
  students, Resume only for already-working applicants.
- **Admin dashboard (`/dashboard`)** — protected by login. Search, filter,
  flag missing documents, change status (New / Reviewing / Shortlisted /
  Rejected), view uploaded PDFs, and export everything to CSV.

Built with Next.js (App Router), Supabase (Postgres + Storage + Auth), and
deployed on Vercel.

---

## 1. Create your Supabase project

1. Go to [supabase.com](https://supabase.com), sign in, click **New Project**.
2. Pick a name and a database password (save the password somewhere safe —
   you won't need it day-to-day, but keep it).
3. Wait ~2 minutes for the project to finish provisioning.

## 2. Run the database schema

1. In your Supabase project, open **SQL Editor** (left sidebar).
2. Click **New Query**, paste in the contents of [`supabase/schema.sql`](supabase/schema.sql)
   from this repo, and click **Run**.
3. This creates one table, `applicants`, with Row Level Security turned on
   and no public access — all reads/writes happen through this app's server
   code using the service role key, never directly from a browser.

## 3. Create the storage bucket

1. Go to **Storage** (left sidebar) -> **New bucket**.
2. Name it exactly: `applications`
3. Leave it **Private** (do not toggle "Public bucket").
4. That's it — no policies to configure. Uploads and downloads both go
   through short-lived signed URLs generated by this app's server code.

## 4. Create your admin login

1. Go to **Authentication** -> **Users** -> **Add user** -> **Create new user**.
2. Enter your own email and a password. Leave "Auto Confirm User" checked.
3. This is the only account that can sign in — there's no public sign-up.
   Use this email/password at `/login` to reach the dashboard.

## 5. Get your API keys

Go to **Project Settings** -> **API**. You need three values:

| Value | Where | Used as |
|---|---|---|
| Project URL | "Project URL" | `NEXT_PUBLIC_SUPABASE_URL` |
| anon / public key | "Project API keys" -> `anon` `public` | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| service_role key | "Project API keys" -> `service_role` `secret` | `SUPABASE_SERVICE_ROLE_KEY` |

The service role key bypasses all security rules — never put it in a
`NEXT_PUBLIC_*` variable, never commit it, never expose it to the browser.
This app only ever reads it from server-side code.

## 6. Deploy to Vercel

1. Go to [vercel.com](https://vercel.com), sign in, click **Add New -> Project**.
2. Import this GitHub repo: `kumar-rpg/AI-RecruitmentDrive`.
3. Before deploying, open **Environment Variables** and add all three keys
   from step 5:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
4. Click **Deploy**.
5. Once it's live, your applicant link is the root URL Vercel gives you
   (e.g. `https://ai-recruitmentdrive.vercel.app`). Share that.
6. Your dashboard is the same domain plus `/dashboard` (e.g.
   `https://ai-recruitmentdrive.vercel.app/dashboard`) — it will redirect you
   to `/login` first.

## Local development

```bash
cp .env.example .env.local
# fill in the three values from step 5 above
npm install
npm run dev
```

Visit `http://localhost:3000` for the application form, and
`http://localhost:3000/login` for the dashboard.

## How it's built (for future reference)

- **File uploads** go directly from the applicant's browser to Supabase
  Storage using short-lived signed upload URLs — the PDF bytes never pass
  through the Vercel server, so there's no risk of hitting a serverless
  function's request-size limit.
- **The public form** never talks to the database or storage directly with
  its own credentials — every write happens through a Next.js Server Action
  using the service role key, after basic server-side validation.
- **The dashboard** is gated two ways: `middleware.js` blocks any
  unauthenticated request to `/dashboard` at the edge, and every server
  action under `app/dashboard/actions.js` independently re-checks the
  session before touching data.
